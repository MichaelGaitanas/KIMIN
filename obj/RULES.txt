Regarding the .obj files that exist in the polyhedra/ directory, the following rules must be satisfied, so that a mesh model can be used in the simulation :

1) The mesh must be a closed manifold geometry (closed polyhedron), e.g. box, sphere, torus knot, potato, etc. However, an open sheet is not considered valid.

2) It does not matter whether or not the mesh is convex. E.g. comet Churyumov Gerasimenko (which is non-convex) is totally fine.

3) The mesh must be triangulated and the face indices in the .obj file must be ordered in a counter-clockwise manner
   when viewed from the front (the side from which the normal points outwards). If the .obj file is generated via a 3D
   modeling software (e.g. Blender) or if it is obtained from a catalog/database, then this assumption is probably already satisfied.

4) In terms of geometry, the .obj file must contain only vertices (in the format 'v x y z') and face indices (in the format 'f i j k').
   Content such as comments, names, vertex groups, etc., is ignored and poses no problem. However, the .obj file must not contain additional
   geometry apart from vertices and faces, such as normals, UVs, line elements, etc.

5) Already existing .obj files are provided in the polyhedra/ directory as examples for use. New meshes can be added in the polyhedra/ directory
   by simply pasting in there and they will automatically appear as available choices in the GUI. At each .obj file, the notation '_R_number_km'
   denotes (approximately) the mean radius of the body in [km].

6) Care must be taken regarding the sizes. Although the binary system of a red supergiant star, along with a tiny cubesat are
   valid in theory, the corresponding detailed mutual roto-translational dynamics and graphics rendering might lack accuracy, as the software is designed
   to handle asteroid-scaled sizes.
   
7) For the currently existing .obj meshes, the vertices are assumed to be in [km].

Regarding the .obj files that exist in axes/ directory, they must not be altered.

---------------------------------------------------------------------------------------------------------------------------------------------------------------

Regarding the .obj files that exist in the mascons/ directory, they basically correspond to polyhedral-mascon-filled models.
At each .obj file, the number '_number_' denotes the number of mascons that form the body. The '_fixed' means that the body has its center
of mass at zero (local coords) and diagonal inertia matrix. The mascon models are not encountered as a modeling method
in KIMIN's GUI. They are only used in the tests/ for testing purposes via the API.
